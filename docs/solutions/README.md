# Solution Store

This directory holds reusable lessons from resolved project problems. Search it
before reopening a familiar design, implementation, debugging, or workflow
question. A solution preserves the durable constraint and links to the current
source owner; it does not replace that owner's reference page.

Organize entries by their kind of reusable lesson:

- `best-practices/` for implementation patterns and technical constraints.
- `conventions/` for durable repository conventions.
- `workflow-issues/` for lessons about planning, verification, or delivery.

Create a solution only when a completed investigation or change yields a
specific lesson likely to prevent repeated work. Keep it concise, use its
frontmatter for discovery, and link to current owners instead of copying their
behavior. Retire or rewrite entries when their constraint no longer applies.

For current source behavior, use [reference documentation](../reference/). For
the full documentation lifecycle, see the
[documentation procedure](../documentation.md).
